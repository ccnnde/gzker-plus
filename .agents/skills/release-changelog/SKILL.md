# 准备发布日志

沿用仓库的 `log:auto` 脚本确定版本、生成日志并暂存；AI 只整理 `src/markdown/ChangeLog.md` 的最新版本段，不重新计算版本。

## 生成

先检查 `git status --short`、最新 Git tag、`package.json` 版本、日志首个版本标题及 staged diff。

- 若当前已有 `log:auto` 生成且尚未发布的版本和日志，直接整理，不要再次运行脚本。
- 否则确认存在待发布提交、工作区干净，再按仓库 `AGENTS.md` 规定的 pnpm 调用方式运行 `log:auto`。该脚本带 `--clean`；不要为通过检查而暂存、提交、丢弃或隐藏其他改动。
- 若无法判断现有版本段是否由本次发布生成，先检查 tag 和相关 diff，不要盲目再次 bump。

## 精简

对照上一个发布 tag 至 `HEAD` 的提交和必要的代码改动，确认每条用户可见变化。只编辑新生成的最顶部版本段，保留版本号、日期、既有 `🚀 新增`／`🔥 优化`／`🐞 修复` 格式以及所有历史版本内容。

- 保留新能力、可感知的交互或性能改进、实际缺陷修复，以及重要的权限或隐私变化。
- 合并同一功能的重复提交和连续修复；用用户能理解的结果描述变化，避免实现名词、空泛的“优化体验”和过细的 UI 调整。
- 省略纯构建、依赖、文档、测试和内部重构事项，除非它们改变了用户实际获得的功能或修复了用户遇到的问题。
- 不凭提交标题猜测行为，不把名称相近但用途不同的变化合并；证据不足时检查 diff，仍无法确认则保留准确的窄描述或报告疑点。
- 不编造功能、不扩大修复范围，也不改写 `package.json` 中由 `log:auto` 生成的版本号。

## 核对

把提交历史作为候选清单，以发布前的当前代码、设置文案和最终行为为准。逐项核对新增、优化、修复提交，确保每项已写入、与相关提交合并或有明确省略理由。

- 检查功能从首次加入到 `HEAD` 的完整生命周期。若后续提交扩展、限制、改名、替换、回滚或删除该功能，日志描述最终状态，不保留已撤销的中间行为。
- 以“上一已发布版本到当前版本的净变化”为判断边界。对每条候选修复，查看其 diff、相关文件历史和引入问题的提交，并与上一发布版本的代码或行为比较：
  - 问题在上一发布版本中已经存在，或由论坛、浏览器等外部变化触发时，作为独立修复保留。
  - 问题由本次尚未发布的新功能、重构或构建迁移引入，并在发布前修复时，不写成独立修复；必要时只在对应新增条目中描述最终可用状态。
  - 修复同时覆盖旧问题和本次开发回归时，只描述上一版用户可能遇到的部分，不暴露发布前的中间缺陷。
- 不能仅因提交类型是 `fix`、提交时间晚于 `feat`，或修改了同一文件就判断归属。提交顺序只能作为线索，最终以发布基线、引入提交和当前实现的对比为准。
- 描述完整的用户能力，不只复述最后一笔增量。例如首次加入“回复预加载”，之后新增更多页数时，应写明支持回复预加载及当前可选范围，不能只写“增加三页、四页选项”。
- 对照当前设置页文案、枚举和默认值，核实选项范围、开关含义和作用条件；对照调用处核实数据范围、触发方式及限制，例如功能使用全部数据还是仅使用已加载内容。
- 区分名称相近的功能，并检查提交内容是否超出标题。例如同名提交可能分别实现“热门回复”和“导出主题”，不能直接去重；配置导入导出的内容范围与“恢复默认”的范围也必须分别确认。
- 检查权限变化、错误提示和交互入口。权限减少与按需授权应准确说明；用户可感知的新入口或错误状态若有独立价值，不应因提交类型是 `perf` 或 `fix` 而遗漏。
- 若 `git describe --tags --abbrev=0`、版本号和日志首段不一致，检查相关 tag 是否为 `HEAD` 的祖先，并比较分叉的发布提交。已经出现在历史版本段中的变化不得因 tag 分叉而重复写入新版本。
- 完成后重新阅读新版本段，对每条做事实检查：主语和动作是否准确、是否遗漏能力主体、是否夸大覆盖范围、是否隐藏重要限制、是否与其他条目重复。

## 收尾

按仓库规定的 pnpm 调用方式运行 `log:format` 和 `log:stage`，因为 AI 修改日志后原有暂存内容已过时。检查 `git diff --cached --check` 和 staged diff：本次发布准备只应暂存 `package.json` 与 `src/markdown/ChangeLog.md`；最新标题版本须与 `package.json` 一致，历史版本段须保持原样。

向用户报告版本号、精简后的本次日志及暂存状态。若没有可确认的用户可见变化，说明原因，不为了凑日志编造条目。本 skill 到此结束，不执行 `zip:all`、Git commit、tag、push、商店提交或 GitHub Release。
