# 输出 README 功能列表

读取当前仓库的 `README.md`，提取“功能”章节，按以下规则输出。功能内容以本次读取的 README 为准，不照抄历史对话中的旧清单，也不将用户提供的格式示例误当作功能内容。

## 内容规则

- 保留 README 的功能顺序、emoji、标题和描述；只调整排版，不添加功能、夸大能力或改写权限含义。
- 保留新增的功能和选项，例如楼中楼、回复预加载、搜索增强、配置管理；不要因为旧格式示例没有这些内容而省略。
- 省略“支持 Markdown 语法”条目下的子级说明，例如语法帮助文档和预览渲染细节，保留该条目本身。
- 将 Markdown 展示语法转换为纯文本：去掉行内代码的反引号、粗体标记和为 Markdown 添加的转义字符，例如 `S\.EE` 输出为 `S.EE`，`@uid` 不带反引号。保留功能子项的 `- ` 列表标记。
- 末尾固定追加 `代码开源：https://github.com/ccnnde/gzker-plus`。

## 排版规则

- 最终回答只包含一个无语言标记的代码块，不使用 `diff`，不添加代码块外的说明。
- 第一行为 `功能列表：`，随后空一行。
- 一级功能去掉 README 的列表前缀，直接以 emoji 开头。
- “💬 用户信息悬浮窗”和“📬 消息增强”各用两行：第一行标题，第二行描述。去掉标题与描述之间的冒号，两行之间不留空行。
- “📋 主题增强”和“📝 编辑器增强”各用一行标题，空一行后列出子项。每个子项以 `- ` 开头，不缩进，相邻子项之间不留空行。
- 其他一级功能保持单行；原文有标题和描述时，保留中文冒号连接，例如 `🔍 搜索增强：…`。
- 各一级功能之间空一行；最后一个功能与开源地址之间也空一行。

```
- 在当前页面直接浏览、创建、编辑和屏蔽主题，以及创建和编辑回复

📝 编辑器增强

- 支持 Markdown 语法，实时预览内容，所见即所得

🎨 支持深色模式切换，并添加多种深色和浅色主题样式

代码开源：https://github.com/ccnnde/gzker-plus
```

输出前核对 README：除 Markdown 语法下的子级说明外，功能是否完整、顺序是否一致；开源地址、空行和代码块是否符合上述格式。
